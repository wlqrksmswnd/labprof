# labprof — 실습실 PC Google 로그인 없애기

실습실 PC는 종료하면 D:를 빼고 전부 초기화된다. 그래서 수업마다 **이메일 → 비밀번호 → 폰 2차인증**을 반복해야 한다.

이 도구는 그 과정을 자동으로 "입력"해주는 게 아니라 **로그인 자체를 없앤다.** 로그인된 Chrome 프로필을 암호화해서 D:에 보관하고, 수업 시작할 때 비밀번호 한 번으로 풀어 쓴다.

```
매 수업:  start.bat  →  번호 하나  →  비밀번호 1회  →  이미 로그인된 Chrome
```

이메일, 계정 비밀번호, 2차인증, 폰 — 전부 필요 없다.

D:에는 암호화된 파일만 있으므로, 다른 학생이 D:를 열어봐도 계정에 들어갈 수 없다.

**여러 사람이 같은 PC를 써도 된다.** 사람마다 컨테이너 파일이 따로 생기고(= 슬롯), 시작할 때 번호로 고른다. 자세한 것은 아래 "여러 사람이 같이 쓸 때".

---

## 파일

| 파일 | 역할 |
|---|---|
| `start.bat` | **매 수업 이걸 실행한다.** |
| `unblock.bat` | D:에 복사한 **직후 1회.** 인터넷에서 받은 파일의 차단 표시를 지운다 (아래 0단계) |
| `collect-env.bat` | 최초 1회 진단 (아래 0단계) |
| `change-password.bat` | 컨테이너 비밀번호 변경 |
| `lab-profile.ps1` | 본체 — 복호화 → Chrome → 종료 대기 → 재암호화 |
| `crypto.ps1` | AES-256-CBC + HMAC-SHA256 컨테이너 |
| `profile-lib.ps1` | Chrome 탐색 / 종료 대기 / 캐시 정리 / 원자적 저장 |
| `slots.ps1` | 슬롯(사람별 프로필) 이름·목록·선택 |
| `log.ps1` | 화면 내용을 `run-log.txt` 로도 남기는 부분 |
| `collect-env.ps1`, `change-password.ps1`, `unblock.ps1` | 위 `.bat`들이 부르는 스크립트 |
| `CHECKLIST.md` | 실습실에서 손으로 하는 2인 왕복 검증 체크리스트 |
| `profile-<이름>.enc` | **생성됨.** 사람마다 하나. 암호화된 프로필, 이게 전부다. |
| `profile-<이름>.enc.bak` | **생성됨.** 직전 세대 백업 (1세대) |
| `run-log.txt` | **생성됨.** 실행 기록 (오류를 나중에 다시 볼 때) |
| `env-log.txt` | **생성됨.** 진단 기록 |
| `boot-error.txt` | **생성될 수 있음.** 스크립트가 시작조차 못 했을 때만 생긴다 (아래 "오류가 났을 때") |

`.bat`은 `%~dp0` 기준 상대 경로를 쓴다 → 폴더째로 어디든 옮겨도 동작한다.

## 0단계 — 이 방식이 이 PC에서 되는지 먼저 확인 (필수)

**건너뛰지 말 것.** 이게 안 되면 나머지가 전부 무의미하다.

Chrome 쿠키는 현재 Windows 사용자의 DPAPI 키로 묶여 있다. 프로필 파일이 살아남아도 그 키가 같이 살아남지 않으면 Chrome은 조용히 새 키를 만들고 기존 쿠키를 버린다 = **로그아웃**.

1. 폴더 전체를 D:에 복사 (예: `D:\GoogleLab\`)
2. **`unblock.bat` 실행** — 인터넷에서 받은 파일에는 차단 표시가 붙어 있어서 실행할 때마다 보안 경고 창이 뜬다. 이걸 한 번 돌리면 없어진다. D:는 초기화되지 않으므로 다음 수업에도 그대로다.
   `unblock.bat` **자신에서는** 경고가 한 번 뜰 수 있다 → **"실행"** 을 누르고, 창에 **"이 파일을 열기 전에 항상 확인"** 체크가 있으면 **해제**한다.
3. `collect-env.bat` 실행
4. **PC를 완전히 종료했다가 다시 켠다** (실제 초기화가 일어나야 한다. 초기화는 종료할 때 일어나므로 "다시 시작"으로는 덜 확실하다)
5. `collect-env.bat` 다시 실행
6. `env-log.txt`를 메모장으로 열어 두 블록을 비교

| 결과 | 의미 | 조치 |
|---|---|---|
| `SID`와 `UserDpapiKeys`가 **같다** | 스냅샷 복원형 (복원솔루션·Deep Freeze류) | ✅ 1단계로 |
| 하나라도 **다르다** | 프로필 재생성형 | ❌ 아래 "안 될 때" |

"D:만 빼고 초기화"는 국내 실습실 복원솔루션의 전형적인 동작이라 같게 나올 가능성이 높다. 그래도 확인은 해야 한다.

같은 파일의 **`BlockedFiles`** 줄도 봐 둔다. `(없음)` 이면 차단 표시가 남아 있지 않다는 뜻이다. 그런데도 보안 경고 창이 계속 뜬다면 원인은 차단 표시가 아니라 **백신이나 실습실 정책**이므로, 스크립트로 해결할 수 없다 → 관리자에게 이 폴더를 예외로 등록해 달라고 요청한다.

## 1단계 — 최초 1회 셋업

1. `start.bat` 실행 → 프로필이 하나도 없으면 바로, 있으면 메뉴에서 `N`을 눌러 **셋업 모드**로 들어간다
2. **프로필 이름**을 정한다 (영문/숫자/한글, 1~24자. 예: `hong`, `홍길동`). 파일 이름이 되고 다음부터 메뉴에 이 이름이 뜬다
3. **컨테이너 비밀번호**를 정해 두 번 입력한다 (아래 "두 개의 비밀번호" 참고)
4. 빈 Chrome이 열린다 → Google 로그인 (이메일 + 비밀번호 + 폰 2차인증)
5. **2차인증 화면에서 "이 기기에서 다시 묻지 않음"을 반드시 체크한다.**
   이게 기기 신뢰 쿠키를 심는다. 놓치면 매번 2차인증이 다시 뜬다.
6. Chrome을 **X로 정상 종료**
7. 콘솔에 `저장 완료`가 뜨는 것을 확인하고 창을 닫는다

## 2단계 — 매 수업

```
start.bat  →  번호 하나  →  비밀번호 1회  →  Chrome
```

```
사용할 프로필을 고르세요:

  1) hong             (마지막 저장: 2026-09-07 14:30, 42MB)
  2) kim              (마지막 저장: 2026-09-01 10:12, 38MB)
  N) 새 프로필 만들기

선택 (번호 또는 이름):
```

최근에 저장한 순서라 자주 쓰는 사람이 대개 1번이다. 번호 대신 이름을 쳐도 되고, `start.bat hong`처럼 실행하면 메뉴를 건너뛴다.

끝나면 **Chrome을 닫고 `저장 완료`가 뜰 때까지 몇 초 기다린다.** 그래야 Google이 회전시킨 최신 쿠키가 반영되어 컨테이너가 오래 유효하다.

⚠️ **Chrome을 열어둔 채 PC를 끄면 그 세션은 저장되지 않는다.** 저장은 Chrome이 닫히는 것을 신호로 시작하기 때문이다. 컨테이너는 지난번 상태로 그대로 남으니 로그인이 풀리는 건 아니지만, 그날 한 일(북마크, 새로 로그인한 사이트 등)은 반영되지 않는다. 나갈 때는 반드시 Chrome을 먼저 닫고 `저장 완료`를 확인한다.

⚠️ **바탕화면의 기본 Chrome 아이콘으로 실행하면 초기화된 빈 프로필이 열린다. 항상 `start.bat`으로 실행할 것.**

제대로 실행됐는지 확인하려면 `chrome://version`의 **프로필 경로**가 `...\Temp\lp`를 가리키는지 보면 된다.

## 여러 사람이 같이 쓸 때

한 폴더에 스크립트 한 벌만 두고, 사람마다 컨테이너 파일이 하나씩 늘어난다.

```
D:\GoogleLab\
    profile-hong.enc          hong 의 프로필
    profile-hong.enc.bak
    profile-kim.enc           kim 의 프로필
    profile-kim.enc.bak
    start.bat, *.ps1          모두가 공유
```

**남의 것은 열리지 않는다.** 파일 이름은 보이지만 경계는 이름이 아니라 컨테이너 비밀번호다. 남의 번호를 골라 자기 비밀번호를 넣으면 Chrome이 아예 뜨지 않고 "비밀번호가 틀렸거나 손상되었습니다"만 나온다.

**이름 규칙** — 영문/숫자/한글과 `.` `_` `-`, 1~24자. 첫 글자는 문자나 숫자. 공백·경로 문자는 못 쓴다.

**다른 사람이 Chrome을 열어둔 채면 시작되지 않는다.**

```
이 PC 에서 이미 프로필 세션이 실행 중입니다.
먼저 열려 있는 Chrome 창을 모두 닫아 그 세션을 끝내야 합니다.
```

작업 폴더를 함께 쓰기 때문이다. 그냥 시작하게 두면 그 사람이 쓰던 프로필이 깨진다. 열려 있는 Chrome을 모두 닫고(그 사람의 `저장 완료`가 뜬 뒤에) 다시 실행한다.

**계정이 여러 개면 슬롯을 늘리지 말고 Chrome 안에서 전환한다.** 학교 계정 + 개인 계정처럼 한 사람이 계정을 여럿 쓸 때는, 한 슬롯 안에서 Chrome 자체의 프로필 전환(우측 상단 아바타 → 추가)을 쓰면 된다. 그러면 비밀번호도 한 번만 치면 된다.

**슬롯 지우기** — 탐색기에서 `profile-<이름>.enc`와 `profile-<이름>.enc.bak`을 지우면 된다. 그 사람이 다시 쓰려면 1단계를 다시 하면 된다(로그인 1회).

⚠️ **같은 폴더를 쓰는 이상 서로의 파일을 지우거나 덮어쓸 수 있다.** 모두 같은 Windows 계정으로 로그인한다면 NTFS 권한으로 막을 방법이 없다. 다만 컨테이너는 로그인 상태의 캐시일 뿐 원본은 Google 계정이므로 **최악의 경우 비용은 로그인 1회**이고, `.bak` 한 세대가 사고성 손상은 한 번 막아준다. 읽히는 쪽은 문제없다 — 복사해 가도 비밀번호 없이는 못 연다.

## 두 개의 비밀번호 — 이 구분이 중요하다

|  | 무엇 | 누가 검증 | 이 도구가 아는가 |
|---|---|---|---|
| **컨테이너 비밀번호** | 내 `profile-<이름>.enc`를 여는 열쇠 | 이 스크립트 (HMAC) | 예 |
| **Google 계정 비밀번호** | 계정 로그인 | Google 서버 | **아니오. 저장도 입력도 안 한다** |

**두 개를 다르게 정하라.** 서로 아무 관계가 없다.

### Google 비밀번호를 바꿨을 때 → 아무것도 안 해도 된다

이 도구는 Google 비밀번호를 모른다. 쿠키 뭉치를 옮기는 일만 한다. 그래서:

1. 컨테이너는 **정상적으로 열린다** (컨테이너 비밀번호는 그대로니까)
2. Google이 세션을 무효화했으므로 Chrome에서 **로그인 화면이 한 번 뜬다**
3. 새 비밀번호로 로그인 → 정상 종료 → 갱신된 쿠키로 저장 → **다음 수업부터 원상복구**

비용은 그 주에 로그인 1회뿐이다. 2차인증이 다시 뜨면 **"이 기기에서 다시 묻지 않음"을 다시 체크**한다.

### 컨테이너 비밀번호 바꾸기

`change-password.bat` → 메뉴에서 자기 프로필 선택 → 기존 1회 + 새 것 2회. 기존 비밀번호가 틀리면 아무것도 변경되지 않는다. 고른 프로필 하나만 바뀌고 다른 사람 것은 그대로다.

변경 후 `profile-<이름>.enc.bak`은 **아직 옛 비밀번호로 열린다.** 옛 비밀번호가 노출돼서 바꾸는 거라면 `.bak`을 지울 것.

## 두 가지 실패를 구분하는 법

둘 다 "로그인이 안 된다"로 체감되지만 원인과 조치가 완전히 다르다. 화면으로 구분된다.

**(a) 컨테이너를 못 열었다**
```
'hong' 의 비밀번호가 틀렸거나 파일이 손상되었습니다.
Chrome 을 실행하지 않고 종료합니다.
```
→ Chrome이 아예 안 뜬다. 비밀번호와 **고른 프로필 이름**을 다시 확인한다.

**(b) 컨테이너는 열렸는데 Google 세션이 만료됐다**
```
컨테이너 열림 (마지막 저장: 2026-09-07 14:30)
```
이 줄이 나왔는데 Chrome에서 로그인 화면이 뜨는 경우다. **컨테이너는 정상이다.** Google 쪽 사정(비밀번호 변경 또는 세션 만료)이므로 한 번 로그인하면 된다. 컨테이너 비밀번호를 의심할 필요 없다.

## 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| PowerShell 창이 뜨기도 전에 **보안 경고 창**이 뜬다 | 인터넷에서 받은 파일의 차단 표시(MOTW). **"실행"** 을 누르고 **"이 파일을 열기 전에 항상 확인"** 체크를 해제한다. 근본 해결은 `unblock.bat` 1회 실행 (0단계 2번). 그래도 계속 뜨고 `env-log.txt` 의 `BlockedFiles` 가 `(없음)` 이면 백신·실습실 정책이므로 관리자에게 예외 등록을 요청한다 |
| 폴더에 `boot-error.txt` 가 생겼다 | 스크립트가 시작조차 못 했다는 뜻이다. 메모장으로 열어 내용을 확인한다 (아래 "오류가 났을 때") |
| `chrome.exe 를 찾을 수 없습니다` | Chrome 미설치. 흔한 세 경로와 레지스트리(App Paths)를 다 봐도 없을 때만 나온다. 정말 있는데도 못 찾으면 `profile-lib.ps1`의 `Find-LPChrome`에 경로 추가 |
| `'...' 이라는 프로필은 없습니다` 하고 y/N을 묻는다 | `start.bat 이름`에서 이름을 잘못 쳤을 때 나온다. **오타라면 그냥 Enter를 눌러 취소한다** (계속하면 빈 프로필이 새로 만들어져 처음부터 로그인해야 한다). 이름 없이 `start.bat`을 실행하면 목록에서 고를 수 있다 |
| `Chrome 프로세스를 확인할 수 없습니다` | 실행 실패. **저장을 건너뛰므로 기존 컨테이너는 안전하다.** 다시 실행 |
| `이미 프로필 세션이 실행 중입니다` | 다른 사람(또는 아까의 내가) Chrome을 열어둔 것. 열려 있는 Chrome을 모두 닫고 다시 실행 |
| `임시 폴더를 지우지 못했습니다` | 남은 프로세스가 폴더를 잡고 있다. 재부팅하면 C:가 초기화되면서 함께 사라진다 |
| 메뉴에 내 이름이 안 보인다 | 다른 폴더에서 실행했거나 파일이 지워진 것. `profile-<이름>.enc`가 `start.bat` 옆에 있는지 확인 |
| 매번 2차인증이 뜬다 | "이 기기에서 다시 묻지 않음"을 체크하지 않았다. 체크하고 정상 종료 |
| 학교 계정(`@...ac.kr`)인데 주기적으로 재인증 | Workspace 관리자가 세션 지속 시간을 강제한 경우. 이 도구로는 못 우회한다 |
| 프로필 경로가 `Temp\lp`가 아니다 | `start.bat`이 아니라 Chrome 아이콘으로 실행한 것 |
| 컨테이너 비밀번호를 잊었다 | 아래 "복구" |
| 저장이 느리다 | 프로필이 커진 것. 캐시는 자동 제외되지만 다운로드·확장 프로그램은 쌓인다 |

### 오류가 났을 때 — `run-log.txt`, `boot-error.txt`

화면에 나온 내용은 `start.bat` 옆의 **`run-log.txt`** 에도 그대로 쌓인다. 실습실 PC는 꺼지면 `C:`가 초기화되지만 이 파일은 `D:`에 남으므로, 오류 화면을 사진으로 찍는 대신 파일을 가져와서 보면 된다. 실행할 때마다 뒤에 덧붙고, 1MB가 넘으면 `run-log.txt.1`로 한 세대만 밀어 둔다.

**`boot-error.txt` 는 평소에 생기지 않는다.** PowerShell 자체가 시작하지 못했거나 `run-log.txt` 를 열기도 전에 죽은 경우에만 내용이 남는다 — 즉 이 파일이 있다는 것만으로 이미 단서다. 그럴 때는 콘솔에 `*** see boot-error.txt ***` 도 함께 찍힌다. 메모장으로 그냥 열면 된다 (한글이 섞여 있어도 읽힌다). 내용을 확인했으면 지워도 되고, 다음 실행 때 문제가 없으면 저절로 지워진다.

**다시 실행하기 전에 한 가지** — 오류가 났다면 재실행 전에 로그를 확인하자. `start.bat`은 비밀번호를 묻기 전에 `%LOCALAPPDATA%\Temp\lp`를 지우는데, Chrome을 닫은 뒤 저장 단계에서 터진 경우라면 그 폴더가 그 세션의 유일한 사본이다. (컨테이너 자체는 안전하다. 잃는 것은 그 세션의 변경분이다.)

비밀번호는 로그에 남지 않는다 — 입력이 화면에 찍히지 않으므로 기록될 내용 자체가 없다. 남는 것은 슬롯 이름, 메뉴 선택, 안내 문구, 오류 메시지다.

### 복구 — 영구히 잃는 건 없다

**`profile-<이름>.enc`는 로그인 상태의 캐시일 뿐이고 진짜 원본은 Google 계정이다.**

비밀번호를 잊었든 파일이 깨졌든 `.bak`까지 못 쓰게 됐든, `profile-<이름>.enc`와 `.bak`을 지우고 **1단계를 다시 하면 끝이다.** 비용은 로그인 1회.

### 중간에 PC가 꺼졌다면

재암호화를 못 했으므로 **그 세션의 변경만 사라진다.** D:의 `profile-<이름>.enc`는 그대로이므로 다음에 열면 이전 상태로 열리고 **로그인은 유지된다.** 최악의 경우가 "지난주 상태로 복귀"이지 "처음부터 다시 로그인"이 아니다.

## 보안

**지킬 것**

- 컨테이너 비밀번호는 **12자 이상, 다른 곳에 쓰지 않는 것**으로. D:가 공용이면 누군가 `profile-<이름>.enc`를 복사해 가서 오프라인으로 대입 공격할 수 있다. PBKDF2 40만 회가 이걸 크게 늦추지만 근본 방어는 비밀번호 강도다.
- **Chrome 비밀번호 관리자에 Google 비밀번호를 저장하지 않는다.** 저장하면 비밀번호를 바꿨을 때 옛 것을 자동완성해 반복 실패하는 혼란이 생긴다.
- 자리를 비울 때 `Win+L`. 세션 중에는 평문 프로필이 C:에 존재하므로 실질적인 위험은 "로그인된 채로 자리를 비우는 것"이다.
- **학기가 끝나면** Google 계정 → 보안 → 내 기기에서 실습실 기기를 **원격 로그아웃**하고, D:의 `profile-<이름>.enc` 와 `.bak`을 삭제한다.

**설계상의 성질**

- D:에 평문 프로필이 존재하는 순간은 **없다.** 복호화는 C: 임시 폴더(`%LOCALAPPDATA%\Temp\lp`)에만, 종료 시 삭제 + 재부팅 시 초기화.
- 그 임시 폴더는 모두가 함께 쓰는 자리이므로, **비밀번호를 묻기 전에** (1) 진행 중인 세션이 있는지 보고 (2) 남아 있는 폴더를 지우고 (3) 압축 중간 산물로 `%TEMP%`에 남은 `lp-*.zip`도 함께 지운다. 그래서 비정상 종료로 남은 앞사람의 평문 프로필이 다음 사람 화면 앞에 그대로 놓여 있는 일이 없다.
- 컨테이너: `AES-256-CBC` + `HMAC-SHA256`(encrypt-then-MAC), 키는 `PBKDF2-SHA256 400,000회`로 유도. MAC이 헤더까지 덮으므로 헤더 변조도 탐지된다. 복호화 전에 MAC을 먼저 검증하므로 틀린 비밀번호로는 평문이 한 바이트도 나오지 않는다.
- 저장은 원자적이다: `.tmp` 기록 → **MAC 검증 통과** → 기존 파일 `.bak`으로 → `.tmp`를 본파일로. 검증을 통과하기 전에는 기존 파일을 건드리지 않으므로, 저장 실패가 로그인 상태를 날리는 일은 없다.
- **컨테이너가 유출됐다고 의심되면 Google 비밀번호를 바꾸면 된다.** 세션이 무효화되어 유출된 쿠키가 즉시 무력화된다 (+ 원격 로그아웃).
- D:/USB에서 실행되는 바이너리가 없다 (`chrome.exe`와 `powershell.exe` 모두 C: 것) → AppLocker류 실행 정책을 피해간다.
- `run-log.txt`에 비밀번호는 들어가지 않는다. 다만 **누가 언제 어떤 프로필을 열었는지는 남고, 같은 폴더를 쓰는 사람이 다 볼 수 있다.** 그게 싫으면 지워도 된다 — 다음 실행 때 다시 만들어지고, 도구 동작에는 영향이 없다.

## 안 될 때 — 폴백

0단계에서 SID/DPAPI 키가 **다르게** 나왔거나, Workspace 정책이 재인증을 강제하는 경우다. 쿠키를 살릴 방법이 없으므로 로그인은 해야 한다. **대신 폰을 없앤다.**

**KeePassXC Portable + TOTP** — `.kdbx` 암호화는 비밀번호 기반이라 DPAPI와 무관해 초기화에 영향받지 않는다. D:에 두고 쓴다.
- Google 보안 설정에서 **Authenticator(TOTP)** 를 2단계 인증 수단으로 추가하고 그 시드를 KeePassXC 항목의 TOTP 필드에 저장 → 6자리 코드를 KeePassXC가 생성해 자동 입력. **폰 불필요.**
- 자동 입력 시퀀스는 Google이 이메일/비밀번호를 두 화면으로 나누므로 `{TAB}`이 아니라:
  `{USERNAME}{ENTER}{DELAY 2500}{PASSWORD}{ENTER}`
- 제약: 고급 보호 프로그램 계정은 TOTP 불가. 학교 Workspace는 관리자가 허용 수단을 제한할 수 있으니 Authenticator 추가가 가능한지 먼저 확인. 포터블 exe를 D:에서 실행해야 해서 AppLocker에 막힐 수 있다.

**FIDO2 보안키 패스키** (YubiKey 등, 3~7만원) — 꽂고 터치하면 비밀번호·2차인증 모두 생략되고 PC에 아무것도 남지 않는다. 초기화 방식과 무관하고 좌석·실습실이 바뀌어도 된다. 가장 확실한 대안.

## 개발자용

동작 확인은 `CHECKLIST.md` 를 따라 실습실에서 한 번 한다. 실제 Google 로그인, 여러 사람이 번갈아 쓰는
상황, 진행 중 세션 차단, 잔여 폴더 정리 — 어차피 진짜 PC 가 있어야 확인되는 것들이다.

스크립트를 고쳤다면 실행 전에 문법만 훑어볼 수 있다:

```powershell
Get-ChildItem *.ps1 | ForEach-Object { $t=$null; $e=$null;
  [void][System.Management.Automation.Language.Parser]::ParseFile($_.FullName,[ref]$t,[ref]$e)
  if ($e.Count) { "$($_.Name): $($e[0].Message)" } else { "ok $($_.Name)" } }
```

컨테이너 형식:

```
"LABPROF1"(8B) | iterations(4B, LE) | salt(16B) | iv(16B) | ciphertext | HMAC-SHA256(32B)
```

- `iterations`를 헤더에 넣으므로 나중에 값을 올려도 기존 컨테이너를 계속 열 수 있다.
- MAC은 자기 앞의 모든 바이트를 덮는다. 비교는 상수 시간(`Test-LPBytesEqual`).
- `AesGcm`과 `CryptographicOperations.FixedTimeEquals`는 .NET Framework 4.8(= Windows PowerShell 5.1)에 **없다.** PowerShell 7 설치를 가정할 수 없어 CBC+HMAC을 직접 조합했다.
- `Rfc2898DeriveBytes`의 기본 해시는 SHA1이므로 SHA256 오버로드를 **반드시 명시**한다.
- 키 유도는 **세션당 1회**만 한다 (이 PC에서 약 1.7초). 저장할 때는 salt를 유지하고 IV만 새로 만들어 같은 키를 재사용한다.
- `.ps1` 파일은 **UTF-8 with BOM**이어야 한다. Windows PowerShell 5.1은 BOM 없는 파일을 시스템 ANSI(한국어 Windows에서 CP949)로 읽어 한글이 깨진다.

슬롯:

- 슬롯은 파일 이름 규칙일 뿐이다 (`profile-<이름>.enc`). 컨테이너 형식·암호화·원자적 저장·백업은 슬롯 도입 전과 **완전히 동일**하다.
- `Get-LPSlots`는 결과를 파이프라인으로 낱개씩 내보낸다. 0개/1개인 경우가 있으므로 받는 쪽은 반드시 `@(Get-LPSlots ...)`로 감싼다.
- 슬롯 이름 검증은 두 겹이다: 입력 시 `Test-LPSlotName`, 경로를 만들 때 `Get-LPSlotPath`가 다시 검사하고 실패하면 throw한다. 경로 조작에 대한 마지막 방어선이라 조용히 넘어가지 않는다.
